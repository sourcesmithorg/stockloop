# Copyable local-agent prompts

Supply real paths and a specific authorized task. These prompts do not require OpenClaw or a particular coding harness. Replace angle-bracket path/task values before use. The owner should not send a whole-roadmap build prompt unless that scope is deliberately authorized.

## 1. Read-only kickoff

> Read README.md, AGENTS.md, PRODUCT-BRIEF.md, BASELINE.md and roadmap.md from `<documentation-pack-path>`. Inspect `<actual-repository-path>` and `<html-template-path>` read-only. Identify existing instructions, stack, changes, available tests and fixture actions. Do not edit, install, scaffold, call providers, send messages or deploy. Return a bounded proposal for SL-01, a source-to-route map and the specific decisions that block later implementation. Distinguish confirmed facts from proposals. Do not treat optional extensions as MVP.

## 2. UI-only task

> Implement `<selected-template-change>` only in `<allowed-paths>`. This is Lane A: static HTML/CSS, no runtime JavaScript/framework/backend/business logic. Read DESIGN.md, UI-UX-GUIDE.md and the applicable feature/state/test sections. Preserve Cornerstore and the existing unrelated changes. If the change is a new major flow, present a task-specific shape brief and wait for confirmation before editing. Otherwise make surgical edits, use labeled fictional data, verify the changed screen in a real browser at desktop and 320/390px, and report keyboard/overflow/state results. Do not deploy or claim real saving/calculations.

## 3. Framework slicing after stack approval

> Work on SL-03 for the approved stack `<stack>`. Allowed paths: `<paths>`. Read the original HTML/CSS and canonical DESIGN.md. Extract the shell, navigation, heading, fields, buttons and inventory identity/table, preserving visual tokens and semantics. Keep business operations as explicit fixtures until their contracts are authorized. Do not redesign, add new dependencies without need, migrate backend, send email or deploy. Run T-01–T-04/T-24 as applicable and provide browser evidence plus limitations.

## 4. Deterministic logic task

> Work on `<SL-10-or-SL-11>` under accepted decisions `<decision-records>`. Read FEATURE-SPECS.md, DATA-CONTRACTS.md, CALCULATION-RULES.md and T-10–T-15/T-19/T-21. Implement the authorized policy at the trusted domain/service boundary, not only in UI. Preserve unknown-versus-zero, pack/unit precision, per-currency totals and version invalidation. Add tests that fail on the relevant edge cases, then pass. Do not adopt unresolved formula/calendar/currency defaults silently. Keep AI out of authority. Report exact fixtures and tests.

## 5. Import vertical slice

> Implement the approved dataset import `<dataset>` with SL-07/SL-08 scope `<paths>`. Accepted schema/encoding/limits/commit/duplicate policies are `<records>`. Build mapping, validation, preview and retry-safe commit around one versioned job. Show unique row counts, blocking versus warning issues and provenance. No success until persisted evidence. Test missing mapping, invalid values, duplicate/overlap, unknown references, failed commit and timeout/retry. Do not infer missing reporting days as zero.

## 6. AI explanation task

> Implement SL-12 only after D-13 is accepted. Provider setup is `<approved-adapter>`, not a model name invented from the template. Read AI-CONTRACT.md and tests T-16/T-17. Keep credentials server-side, minimize inputs, validate output schema/IDs/versions/facts/candidates and handle provider failure with labeled rule-based fallback. AI cannot approve, export, send or redefine prices. Add prompt-injection and stale-response tests. Do not make live spend/provider calls outside the task's explicit scope.

## 7. Approval/export task

> Implement `<SL-13-or-SL-15>` with accepted permissions/version/document policy `<records>`. Use trusted server-side eligibility checks and immutable reviewed content. Test quantity/terms/import changes after approval, concurrent edits, unauthorized actor, duplicate clicks and ambiguous outcome reconciliation. One document per supplier/currency. Export is not sending or placing an order. Preserve preview on failure and report artifact content/version evidence. No supplier email or production deployment.

## 8. Independent review

> Review `<task-change-paths>` read-only against `<task-id>`, DESIGN.md, FEATURE-SPECS.md and applicable test IDs. Do not edit files, install, deploy or send external messages. Report only verified findings, with P0–P3 severity, exact path/selector, expected versus observed behavior, impact and minimal correction. Check entity identity, fixture boundaries, arithmetic, calendar assumptions, accessibility/state/mobile behavior and approval safety. State what was inspected/tested and what was not. Return a concise report to the task owner.

## 9. Final handoff

> Reconcile the selected task's acceptance criteria. Run feasible tests and browser checks, fix task-owned regressions, preserve unrelated changes and report using HANDOFF-TEMPLATE.md. List pass/fail/not-run outcomes. Do not claim real-device, cross-browser or WCAG certification from automated Chromium alone. Do not mark complete while required work fails. Commit/push/deploy only if explicitly authorized.

## Prompt mistakes to avoid

- “Build everything in the roadmap” without decisions/write scope.
- “Make it functional” while the task remains HTML-only.
- “Use any backend/model you like” when ownership/provider policy is unresolved.
- “Auto-send approved orders” when only export is authorized.
- “Keep old approvals after edits” or “convert all money to the new preference.”
- “Show success no matter what” or “ignore invalid rows silently.”
